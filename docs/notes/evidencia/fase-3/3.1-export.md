# Evidencia ítem 3.1 — `core/export` (2026-10-13)

Módulo Kotlin JVM puro (sin Android): recibe un `TripExport` (viaje, etapas, puntos,
pausas, paradas, medios, notas) y escribe cada formato a un flujo de salida. El ZIP
(`ExportPackage`) se arma en streaming, copia los archivos que la app le abre y
escribe `LEEME.txt` al final con la conciliación.

## Formatos y cómo se verifican (19 tests, todos verdes)
| Archivo del ZIP | Qué es | Prueba |
|---|---|---|
| `trip.json` | Todo el viaje; contrato con el renderizador de escritorio | Valida contra `docs/trip.schema.json` (JSON Schema 2020-12) con una librería de validación solo en tests; horas con offset de la etapa y en ms UTC |
| `tracks/viaje-completo.gpx`, `tracks/NN_fecha_etapa.gpx` | GPX 1.1, un `<trk>` por etapa, `<trkseg>` nuevo en cada pausa, fotos/notas/paradas como `<wpt>` | Valida contra el XSD oficial (`core/export/src/test/resources/gpx.xsd`); cuenta de trkseg = pausas + 1; filtrados excluidos salvo pedido; escape de `& < > "` |
| `tracks/viaje.kml` / `viaje.kmz` | Carpeta y estilo por etapa, recorrido simplificado a 30 m, `Placemark` con descripción HTML; KMZ con miniaturas | Bien formado; coordenadas `lon,lat,alt`; menos vértices que puntos; KMZ contiene `doc.kml` + `files/` |
| `tracks/viaje.geojson` | `FeatureCollection` RFC 7946 | Una `Feature` por etapa y por evento, posiciones `[lon, lat]` |
| `tablas/puntos.csv`, `medios.csv`, `notas.csv`, `lugares.csv` | Planillas UTF-8 con BOM, RFC 4180 | Re-parseo propio: conteo de filas y texto con comillas, comas y emoji intacto |
| `bitacora.md`, `bitacora.html` | Diario cronológico (usa `core/timeline`); HTML autocontenido con Leaflet desde CDN y los datos embebidos | Encabezados por día y etapa, enlaces relativos; el JSON embebido se vuelve a parsear y no contiene `</script` |
| `subtitulos/notas.srt` | Notas de voz como subtítulos, hora relativa al inicio de la etapa | Formato `HH:MM:SS,mmm`; notas sin texto no generan cue |
| `LEEME.txt` | Cómo abrir cada archivo + conteos base vs. ZIP + faltantes | Test de conciliación: una foto y un audio ausentes quedan listados y los conteos coinciden con la base |

## Decisiones
- Sin extensiones de Garmin en el GPX: transportan datos de sensores (pulso, cadencia) que la app no tiene. Las extensiones propias `bv:speed`, `bv:hacc` y `bv:filtered` llevan lo que sí existe; `hdop` aproximado desde la precisión horizontal.
- Límites de Google My Maps (10 capas, 2.000 elementos por capa) aplicados como constantes; se recortan los placemarks por etapa si hiciera falta. Revalidar antes de la Fase 6.
- `lugares.csv` lista las paradas detectadas hasta que exista la tabla de lugares (Fase 4).
- Dependencias nuevas: `kotlinx-serialization-json` 1.11.0 (misma versión que el core ya fijado) y, solo en tests, `io.github.optimumcode:json-schema-validator` 0.5.5 (última en Maven Central, 2026-06).
